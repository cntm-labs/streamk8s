แนวทางการออกแบบระบบ Hardware Monitoring (Option A)

เน้นความยืดหยุ่น และการจัดการโมดูลภายใน (Internal Library Pattern)

Rust Backend Architecture: src-tauri/src/hardware/
hardware/
├── mod.rs          (Trait definitions: Collector)
├── generic.rs      (CPU/RAM via sysinfo)
└── nvidia.rs       (GPU via nvml-wrapper or custom low-level)

ข้อเสนอในการจัดการ Crate และ Implementation:

1. Use Official Crates (Recommended for Stability)

ใช้ sysinfo และ nvml-wrapper เป็นฐานการทำงานเบื้องต้นเพื่อให้ฟีเจอร์ "Auto-Suspend" ใช้งานได้จริงเร็วที่สุด

2. Custom Implementation (Targeted)

สำหรับส่วนที่สำคัญ เช่น การเรียกใช้ NVML APIs โดยตรง หรือการดึงข้อมูลเฉพาะทางที่เราต้องการทำเองเพื่อประสิทธิภาพสูงสุด

ข้อดีของแนวทางนี้

  • แยกส่วน Driver ชัดเจน (ขยายไป AMD/Intel ได้ง่าย)
  • รองรับการย้ายเข้า Kellnr ในฐานะ Internal Crate
  • ได้ Dashboard ที่มีข้อมูล Real-time ทันที
